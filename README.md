# CGC SQUARE: AI photo kiosk

Webcam photo, pick a look (Sci-Fi, Anime, Cats, Vintage), and a local AI model repaints it.
If the AI isn't set up (or is too slow) it falls back to quick looks, and it still works if the server is down.

## Start everything with one command

Double-click **`start_kiosk.bat`** (or run it in a terminal). That is the only thing you need to run.

The first time it sets everything up (after that it takes seconds, because anything already fine is skipped):
1. installs missing Python libraries and fixes the OpenCV / NumPy 2 mismatch
2. with an NVIDIA GPU: asks once, then installs the GPU build of PyTorch (about 3 GB) and downloads the AI model (about 2.3 GB)
3. if `credentials.json` is present but you haven't signed in to Google yet: opens the one-time Google sign-in
4. starts Ollama only if the AI painter isn't in use
5. starts the server, waits until the AI model is loaded, then opens the kiosk full screen in Chrome or Edge

The AI model download (about 2.3 GB) happens on the first start and can take 15 minutes or more on a slow connection. The
launcher waits about 2.5 minutes for it, then opens the kiosk anyway: photos use the quick looks until the download
finishes, then the AI switches on by itself (the window prints `[AI] ready`). If the connection drops, the download resumes
where it stopped. Keep the launcher window open. After the first time the model is on your computer and starts in seconds.

Stop it with Ctrl+C in the launcher window. In the full-screen kiosk, Alt+F4 closes the browser. Options:
`start_kiosk.bat --check` shows what is missing without changing anything, `--window` opens a normal window instead of full screen,
`--yes` answers every question with yes, `--no-ai` skips the AI painter, `--no-browser` skips opening the browser.
The first time, allow the camera when Chrome asks; it is remembered (the kiosk uses its own browser profile in `.browser_profile`).

The sections below explain each part, and how to run things by hand (`py server.py`) if you ever want to.

## Run by hand (optional)

```bash
cd kiosk
pip install -r requirements.txt
python server.py          # on Windows: py server.py
```

Open http://127.0.0.1:5000 and allow the camera.

## Controls (keyboard only)

| Key | Does |
|---|---|
| **SPACE** | Take the photo (3-2-1 countdown, then the AI repaints it). Press SPACE again to go on to the next student |
| **A / B / C / D** | Sci-Fi / Anime / Cats / Vintage |

There are no capture, retake or download buttons. The result stays up for 45 s, then the camera comes back by itself.
Every photo is **saved automatically** as `photos/1.png`, `2.png`, `3.png` ... on this computer (the numbering carries on
after a restart) and uploaded to the Google Drive folder under the same number. The number is shown next to the QR code,
which links to the Drive folder, so students scan it and pick out their photo by its number.

**Photo-booth print:** the picture shown on screen and saved (`photos/N.png`, 1024x1200, and the Drive copy) is a dark
cardboard photo-booth frame: your picture in the window, a collage of die-cut paper tech stickers around it (a different
arrangement for every print), bunting across the top, paper flowers in the corners, and `#Parivartan2k26` in chalk with a
location pin and `CGC Landran` on the bottom strip. To change that text, edit `EVENT_TAG` and `EVENT_PLACE` near the top of the
photo-booth print section in `svgfx.js` (search for `EVENT_TAG`). The stickers are the `ICONS` list in the same file.

## The four looks

| Look | What you get |
|---|---|
| **Sci-Fi** | Your background is replaced by a cyberpunk lab (sunset skyline, drones, hologram globe, blueprint panel, neon strips) and you get a cyan/orange rim light. Needs the person cut-out; without it you get a retro-future frame around your normal photo instead. |
| **Anime** | A cel-shaded illustration of the whole picture: flat colour patches, clean contour lines, soft glow. Nothing is added on top. |
| **Cats** | A warm illustration with kittens on your head and shoulders, chalk doodles (cat faces, paws, hearts) around you and little motion ticks. |
| **Vintage** | Monochrome sepia photobooth: film grain, dark vignette, soft focus, film streaks. |

**Face outline:** the camera view shows an outline to put your face in (with dashed spots for the kittens on the
Cats look). The stickers are placed from that outline, so they land in the right place. It is only a guide and
is not in the saved photo.

**Person cut-out (Sci-Fi):** `segment.py` runs the small U^2-Net-lite model in `models/u2netp.onnx` (Apache-2.0, 4.6 MB,
included, no download needed) through `onnxruntime`. If it is missing, or the result doesn't look like a person where the
outline is, Sci-Fi quietly uses its framed look.

## AI repainting (real image generation)

The photo is regenerated by **Stable Diffusion img2img** on your GPU, not filtered. It uses the recipe from the
diffusers docs, sized for a 4 GB card like the RTX 3050: a Stable Diffusion 1.5 checkpoint
(`Lykon/dreamshaper-7`, fp16, about 2 GB) plus an LCM-LoRA (`latent-consistency/lcm-lora-sdv1-5`) so it only needs
about 4-5 denoising steps at 512x512. Anime, Cats and Sci-Fi are repainted this way (Cats then gets its SVG kittens on
top); Vintage keeps its film look unless you add it to `AI_THEMES`.

One-time setup:

```bash
pip install -r requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cu124     # the CUDA build of torch
python setup_ai.py my_selfie.jpg      # downloads the model (~2.3 GB, needs internet once), then times every look
python server.py
```

`setup_ai.py` prints the seconds each look takes on *your* GPU and saves `ai_test_<look>.jpg` so you can judge the
result. After that the kiosk works offline. If your GPU memory is too tight it switches itself to CPU offload (slower).

**What the AI painter generates per look** (Stable Diffusion img2img, then light overlays on top):
- **Sci-Fi:** two passes. A strong repaint invents the lab around you (holograms, neon, sunset skyline), a gentle one keeps your face,
  and they are merged with a person cut-out plus a cyan/orange rim light. The HUD corners go on top. Without a usable cut-out it does one balanced pass.
- **Anime:** the whole picture is repainted as an anime illustration; sparkles and petals drift over it.
- **Cats:** warm anime-style repaint; the kittens and chalk doodles are drawn on top.
- **Vintage:** keeps its film look (add it to `AI_THEMES` to repaint it too).
Strengths and prompts are in `STYLES` in `ai_painter.py`. `AI_STRENGTH_SCALE` (e.g. 1.2) makes every repaint bolder.

**If a photo does not look AI-generated:** everything the server prints is also saved in `kiosk.log` (the last run is `kiosk.previous.log`).
A photo gets the quick filter look when the model is still loading, when the AI took longer than `AI_BUDGET`, or after 3 AI errors in a
row (it rests for 1 minute). The log says which, with lines starting `[AI]` and `[Look]`.

**How to tell whether the AI painter is running:** look at the first lines the server prints.
`[AI] repainting with Lykon/dreamshaper-7 for: Sci-Fi, Anime, Cats` means it is on. `[AI] repainting off (...)` means it is not,
and the text in the brackets says why (usually torch without CUDA, or the model not downloaded yet: run `python setup_ai.py`).
While it is off, photos use the quick looks (flat filter styling), which look much less like a repaint.

Quick looks and AI both get an automatic exposure fix first (`exposure.py`): webcams that expose for the bright wall leave the
face too dark, so the brightness inside the face outline is measured and corrected. Put your face inside the outline.

Tuning (environment variables, all optional):

| Variable | Default | Meaning |
|---|---|---|
| `AI_STRENGTH_SCALE` | `1.0` | Lower (0.8) keeps faces closer to the photo, higher (1.2) repaints more boldly |
| `AI_THEMES` | `Sci-Fi,Anime,Cats` | Which looks are repainted by AI (add `Vintage` if you like) |
| `AI_BUDGET` | `24` | Seconds after the shutter press before it gives up and uses the quick look |
| `AI_SIZE` | `512` | Working size. Keep 512 on 4 GB; use 448 if it is slow |
| `AI_MODEL` | `Lykon/dreamshaper-7` | Any Stable Diffusion 1.5 style checkpoint (Hugging Face id or local folder) |
| `AI_LCM_LORA` | `latent-consistency/lcm-lora-sdv1-5` | `none` switches to the normal sampler (about 5x slower) |

Prompts and per-look strengths live in `STYLES` in `ai_painter.py`. A strength near 0.5 keeps the pose and face layout;
higher values change more. If the AI fails twice in a row it is paused for 5 minutes and the quick looks are used.
Ollama is not used while the AI painter is active: both would compete for the 4 GB of GPU memory.

## Quick looks and Ollama (used when the AI painter isn't available)

Ollama's normal models read pictures but don't draw them. So Ollama acts as an art director:
a vision model looks at a small copy of the photo and returns a tiny JSON "recipe" (caption, palette,
three tone numbers: brightness, saturation, warmth). `ai_generator.py` renders it with Pillow and the browser adds the SVG scene, stickers and frame. The
look itself (shading, outlines, kittens, scene) is fixed per theme, and the model's palette is blended halfway
with the theme's own colours, so a model can nudge the photo but never break or recolour the look.

```bash
ollama pull moondream      # ~1.7 GB, fits entirely in a 4 GB GPU: the fastest choice
ollama pull qwen2.5vl:3b   # smarter, but on a 4 GB GPU it spills to the CPU and is much slower
ollama serve               # skip if the Ollama app is already running
```

The server auto-picks the fastest installed vision model (moondream, then llava-phi3, then qwen2.5vl...).

## Speed (a photo in well under 30 seconds)

- Pressing CLICK PHOTO starts the Ollama step immediately, so it runs during the 3-second countdown.
- Ollama only writes about 60 tokens from a 384px picture.
- `LOOK_BUDGET` (default 14 s, counted from the button press) is a hard deadline: if Ollama hasn't
  answered by then, the standard look is used. The worst case is about 15 s.
- If Ollama misses the deadline twice in a row it is skipped for 5 minutes, so photos stay at ~4 s.
- The server prints how long each step took. Raise `LOOK_BUDGET` (up to ~25) if you'd rather wait
  longer for the AI's tweaks.

| Variable | Default | Meaning |
|---|---|---|
| `OLLAMA_MODEL` | auto | Force a model, e.g. `qwen2.5vl:3b` |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | Where Ollama listens |
| `LOOK_BUDGET` | `14` | Seconds after the button press before the AI step is abandoned |
| `PORT` / `HOST` | `5000` / `127.0.0.1` | Server address (`HOST=0.0.0.0` exposes it to the LAN) |
| `SD_API_HOST` | unset | Optional Stable Diffusion WebUI, e.g. `http://127.0.0.1:7860` |
| `SD_THEMES` | `Anime` | Which looks use Stable Diffusion when it is set |
| `SD_SIZE` | `512` | Image size sent to Stable Diffusion (512 fits a 4 GB GPU) |
| `GDRIVE_FOLDER_ID` | unset | Drive folder for uploads |

Windows (PowerShell): `$env:OLLAMA_MODEL="qwen2.5vl:3b"; py server.py`

## Fallback chain

1. **AI repainting** (`ai_painter.py`): Stable Diffusion img2img. Used whenever torch, a CUDA GPU and the model are available.
2. **Stable Diffusion WebUI** (only if `SD_API_HOST` is set, Anime by default), an alternative if you already run one.
3. **Ollama recipe + Pillow** quick look, only when the AI painter isn't available.
4. **Standard quick look** (the theme's default recipe) if Ollama is off, slow or returns junk.
5. **SVG filters in the browser** (`svgfx.js`) if the server can't be reached.

Frame, stickers and caption are SVG in every case, and the preview is the exact SVG that gets saved.

## Google Drive setup (for the QR code)

You need: a Google account, a free Google Cloud project, internet on the kiosk computer, and about 10 minutes, once.
Use a normal Google account (for example a dedicated one such as `cgcsquare.photos@gmail.com`); photos count against its
15 GB of Drive space. **Do not use a service account**: service accounts have no Drive storage of their own, so uploads
to a normal Drive fail with "storage quota" errors.

1. Go to https://console.cloud.google.com/ and create a project (any name).
2. **APIs & Services > Library**, search for **Google Drive API**, click **Enable**.
3. **APIs & Services > OAuth consent screen** (shown as *Google Auth Platform* in newer consoles):
   User type **External**, fill in the app name (e.g. "CGC SQUARE") and your email. Add the scope
   `.../auth/drive.file` (it is *non-sensitive*, so no Google verification is needed).
   Add your Google account as a **Test user**.
4. **Important: publish the app.** On the same screen click **Publish app / Make external to production**. If you leave it on
   *Testing*, Google expires the sign-in after **7 days** and the uploads stop. In production without verification it keeps
   working (you may see a "Google hasn't verified this app" screen once during sign-in: **Advanced > Go to CGC SQUARE**).
5. **APIs & Services > Credentials > Create credentials > OAuth client ID**, application type **Desktop app**. Download the JSON
   and save it in the `kiosk` folder as **`credentials.json`**.
6. Run `python setup_drive.py`. Your browser opens, sign in and click Allow. The script saves `token.json`, creates the folder
   **"CGC SQUARE Photos"** in that account's Drive, sets it to "anyone with the link can view", tests an upload and prints the
   folder link. From now on no browser is needed.
7. Start the kiosk: `python server.py`. The QR code appears on screen as soon as Drive is connected.

What it does and doesn't do:
- The QR code always points at the **folder**, not at one photo. Photos are named `1.png`, `2.png`, ...; numbers already in the
  Drive folder are never reused.
- Uploads run in the background and are retried, so a Wi-Fi drop never loses a photo: it is already saved locally, and anything
  missing from Drive is uploaded when the connection returns (also after a restart).
- Because the folder is "anyone with the link", a student who scans the QR can see **every** photo in it. If that is a privacy
  concern, tell students to find only their number, or create one folder per event and change it afterwards.
- Keep `credentials.json` and `token.json` private (they are in `.gitignore`). If sign-in ever expires or you change the Google
  account, run `python setup_drive.py` again. `GDRIVE_FOLDER_NAME` renames the folder the app creates.

Requirements checklist: Google account, Drive API enabled, OAuth consent screen **published**, Desktop-app OAuth client
(`credentials.json`), `pip install -r requirements.txt` (includes `segno` for the QR code and the Google libraries), internet
access on the kiosk computer.
